# DIWU-63 候补与递补回归

在 QA 仓根目录运行。脚本仅依赖 Python 3 标准库，在第一条不匹配断言处退出。输出逐请求 JSON，包含方法、地址、测试身份、幂等键、输入、HTTP 状态和响应体，末行给出运行模式。

```sh
python3 waitlist/regression.py --stub
python3 waitlist/regression.py --url http://127.0.0.1:18063
```

第一条命令会启动独立内存桩并自动关闭。第二条命令连接已迁移的本轮 API，使用专用测试库。默认使用 env-a 在 2030-01-02 和 2030-01-03 的 10:00–11:00 UTC；成功递补会保留历史队项，请在干净的隔离库复跑固定样例，或用 `--day YYYY-MM-DD` 指定新的连续两天。脚本仅经 HTTP 准备数据。

| 场景 | 核对内容 |
| --- | --- |
| 入队与权限 | 缺失及未知身份 403；缺幂等键 400；空闲时段拒绝候补；同键同负载返回原 ID，异负载返回 KEY_REUSED，不同键重复候补返回 ALREADY_WAITING。 |
| 查询 | GET 只返回本人队项；env-b 与相邻时段为空；同一人多个重叠队项按入队顺序返回。 |
| 分段释放 | alice 预约前半小时，admin 维护后半小时。bob、carol 顺次候补整段；越权撤销返回 403，原记录仍有效。撤预约后两人仍等待；撤维护后仅 bob 晋升，其 bookingId 指向本人整段预约。 |
| 再次释放 | 重复撤维护保持 bob 原预约；撤 bob 后 carol 晋升；重复撤 bob 保持 carol 原预约；清理后 active 列表为空。 |
| 跳过受阻者 | 同一个人先候补整段，再候补前半段。双客户端同时撤前半段预约，应只晋升后一项。撤维护后整段仍受晋升预约阻挡，再释放后整段才能晋升。 |

桩的 HTTP 服务串行处理请求，用于验证回归断言和界面状态。并发事务、条件更新、约束与回滚须在专用 InnoDB 中验收。

### 浏览器复现

启动独立桩 `python3 waitlist/contract_stub.py 18063`，按 Web 工程说明设置 `DEV_API_TARGET=http://127.0.0.1:18063` 并在独立 loopback 端口打开候补页。先准备前半段预约与后半段维护，然后以 bob 和 carol 在页面分别查询、候补同一整小时。释放前半段、释放后半段、重复释放、释放晋升预约后分别刷新。核对页面的本人队项、状态和晋升预约号，核对 Network 每次 GET/POST 的身份、参数、响应和 Console 错误。真实联调时改接版本已固定的 API。

### 核对真实数据库终态

在业务 API 所用的同一专用数据库上执行 HTTP 回归后，切到本轮 API 仓根目录，使用该仓锁定的驱动与 sqrl 依赖运行 `go run /绝对路径/qa-waitlist/waitlist/dbcheck.go -day 2030-01-02`。从本机配置注入 MYSQL_DSN。检查器对两天分别核对 3 条已撤预约、1 条已撤维护、2 条已晋升队项及双向唯一关联、身份和时间边界。库中应只含本次样例在对应范围内的数据。

`python3 waitlist/routes/run.py /绝对路径/API候测工作树` 用 Go overlay 将 QA 测试加载到候测模块，通过实际 Gin 注册函数执行六个请求，核验身份、幂等键、区间和查询参数拦截。请求应在访问仓储前得到拒绝，可在无数据库时执行。
